# 🏙️ Technical & Operational Frequently Asked Questions: Smart City Cluj IoT Core

This document addresses the most common architectural, security, and data management questions regarding the urban control platform.

---

### Q1: Why do the charts in the Streamlit dashboard continue to update smoothly, and why has the terminal stopped showing layout deprecation warnings?
* **Answer**: In earlier Streamlit versions, certain sizing properties could trigger deprecation warnings during auto-refresh cycles. We globally replaced those legacy syntaxes with native, stable layout parameters (such as fluid container layouts and explicit `use_container_width=True` flags) across all active pages (`Dashboard`, `Settings`, `Analytics`), ensuring responsive viewport scaling with zero console warnings.

### Q2: How does the simulator guarantee data isolation and 100% offline execution inside containerized environments?
* **Answer**: The platform enforces defensive global state initialization directly inside `main.py`, completely eliminating network or external cloud API dependencies for storage, threshold management, and local alerting. The system directly queries the central `DATABASE_PATH` database managed transactionally through the `CityRepository` class. All cross-page navigation `KeyError` regressions are completely neutralized via structured checks on `st.session_state`.

### Q3: What happens to city monitoring if the primary LLM cloud provider (Groq) hits rate limits or experiences an outage?
* **Answer**: `FallbackAiProviderRouter` first rotates across configured Groq keys (`GROQ_API_KEY*`) and candidate models (`qwen/qwen3.8-27b`, `openai/gpt-oss-20b`, `openai/gpt-oss-120b`). If Groq is rate-limited or unreachable, the router automatically fails over to **Google Gemini (`gemini-3.5-flash` -> `gemini-3.8-flash`)** via the native `google-genai` SDK. If both external providers are offline, the system logs the structured error via `LOGGER.error` and renders a controlled message in the UI while SQLite persistence, Plotly charts, and the 10-second cooldown `AlertManager` (`security_alerts.log`) continue operating 100% uninterrupted offline.

### Q4: How does the context-aware RAG pipeline deliver grounded AI recommendations without overloading the model's context window?
* **Answer**: Instead of streaming raw database tables into the prompt, `TelemetryContextReader` and `SopKnowledgeRetriever` build a compact, bounded evidence package: current station readings and authorized thresholds, a directional trend summary across the latest 5 `city_stats` records, the top 2 municipal SOP passages retrieved via TF-IDF and cosine similarity (`docs/cluj_urban_sop.md`), and strictly the latest 5 lines from `security_alerts.log`. This dense context is rendered into the validated `app/ai/prompts.yaml` template and sent to `qwen/qwen3.8-27b` (with automatic failover to `gemini-3.5-flash`), followed by deterministic numeric grounding checks.

### Q5: How does the application protect operator session data (`st.session_state`) against Session Cross-Talk attacks in a multi-user cloud environment?
* **Answer**: The Streamlit runtime spins up a completely isolated execution context for every browser tab opened by a new user. All variables stored inside `st.session_state` (such as the `authenticated` flag, active language selection, or response history generated by `qwen/qwen3.8-27b`) reside in a dedicated, thread-isolated memory container bound exclusively to that execution session. There is zero risk of one cloud operator accessing another operator's session state, guaranteeing strict data privacy and isolation per individual session.

### Q6: How does the About page report live quality metrics without hardcoding scores?
* **Answer**: The **Systemic Quality & AI Compliance Control Center** (`pages/4_About.py`) parses the latest JSON artifacts on disk via Pydantic v2 contracts (`PytestSummary`, `GuardrailSummary`, `LlmEvalSummary`). In `ai_tests/llm_eval_report.json`, **Scenario Compliance** (`success_rate_percentage`) is computed dynamically from deterministic keyword matches in the `Assessment` section, while **Average Faithfulness** (`avg_faithfulness_score`) is the arithmetic mean of `1–5` grounding scores returned by `LlmJudgeVerdict`. Clicking **Run Live Architecture Verification** re-executes the suites on demand and updates the displayed metrics.
