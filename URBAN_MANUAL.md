# 1. Urban Executive Summary

## 1.1 Platform Purpose
Smart City Cluj-Napoca IoT Core is an industrial-grade educational Civic Decision Support System (CDSS) engineered to simulate real-time monitoring, evaluation, and automated alerting of environmental and traffic indicators across the municipality of Cluj-Napoca.

The platform integrates:
- Real-time environmental monitoring (Temperature, PM2.5 Air Quality, Noise Level, Traffic Density, Soil Moisture).
- Deterministic asynchronous operational rule engines built on the OOP architecture in `main.py`.
- Local disk-based emergency auditing and logging (`security_alerts.log`) featuring cooldown throttling and anti-log-injection protection.
- Direct atomic schema insertions into the local SQLite database via the `CityRepository` class, dynamically bound to the `DATABASE_PATH` environment variable.
- AI-assisted operational synthesis powered by a Context-Aware LLM via `FallbackAiProviderRouter` (querying `qwen/qwen3.8-27b` on Groq with multi-key rotation and automatic failover to `gemini-3.5-flash` via the native `google-genai` SDK).
- Programmatic evaluation frameworks executed locally via `run_llm_eval.py` with structured JSON reporting.

The core objective is to demonstrate how modern Generative AI pipelines can be safely integrated into civic governance applications without sacrificing operational determinism, local security, or code traceability.

## 1.2 Core Philosophy
The platform operates on three foundational principles:
- **Proactive Mitigation**: Environmental degradation and urban grid malfunctions must be detected prior to catastrophic failure (e.g., severe respiratory hazards or complete soil desiccation in green zones).
- **Absolute Determinism**: Emergency civic actions must rely strictly on trusted data sources and verified values inside `app.db`, never on probabilistic outputs from language models.
- **Traceable Governance**: Every automated urban recommendation must map directly to measurable, immutable sensor readings persisted in the database through safe transactions.

# 2. Physiology of Urban Environmental Degradation

## 2.1 Urban Heat Island (UHI) Effect & Thermal Stress
Dense urban cores in Cluj-Napoca experience ambient thermal energy accumulation driven by continuous solar absorption in concrete and friction generated by heavy vehicular combustion. The platform models this phenomenon through a dynamic mathematical correlation inside the page state generator engine, where elevated traffic volume directly amplifies ambient heat indices and noise levels (dB).

## 2.2 Particulate Matter Air Pollution (PM2.5)
Fine particulate matter PM2.5 (scientifically measured in μg/m³) poses an acute cardiovascular and environmental hazard across high-density transit hubs. The platform enforces strict thresholds: exceeding 80.0 μg/m³ triggers immediate visual warnings on the dashboard and sanitized entries in the audit log to prevent population-level respiratory exposure.

# 3. Deterministic Rule Engine & Risk Stratification

The system rejects black-box probabilistic models for urban safety enforcement. Instead, the logic performs deterministic matching against fixed thresholds stored in the `settings` table of the local SQLite database, queried through isolated methods. To prevent false alarms at boundary values (Alert Fatigue), evaluations enforce strict inequalities:

- **Acute Air Pollution Hazard**: `air_quality (PM2.5) > 80.0 µg/m³`
- **Extreme Thermal Anomalies (Heatwave)**: `temperature > 32.0°C`
- **Critical Ecological Soil Depletion**: `soil_moisture < 35.0%`

# 4. Cybersecurity Architecture & Contextual Ingestion
Civic applications are prime targets for prompt injection attacks. To harden the pipeline, the system decouples raw user queries and enforces a strictly isolated prompt structure using unified variables within `app/ai/prompts.yaml`.

Furthermore, the urban assistant performs dynamic live security context injection directly into the prompt structure by reading the latest 5 lines from `security_alerts.log`. This ensures the LLM generates recommendations grounded in real incident history within a completely isolated boundary, stripping internal `<think>...</think>` reasoning tags via regular expressions.

# 5. Python MLOps Validation Suite

To ensure the AI engine maintains linguistic alignment across the languages selected in the Streamlit interface, `run_llm_eval.py` evaluates scenarios using `qwen/qwen3.8-27b` (with automatic failover to `gemini-3.5-flash`) and compact JSON judging.

The programmatic evaluator runs seven Cluj-Napoca urban scenarios through the Groq-to-Gemini router. It
normalizes diacritics, verifies focal terms inside the `Assessment` section, applies
adaptive pacing, and retries transient rate-limited responses. Each run computes two dynamic metrics without hardcoded values:
- **Deterministic Scenario Compliance (`success_rate_percentage`):** Percentage of scenarios containing the expected telemetry term in `Assessment`.
- **Semantic Faithfulness (`avg_faithfulness_score`):** Arithmetic mean of the `1–5` grounding scores returned by `LlmJudgeVerdict` and parsed dynamically on the **About** page via `LlmEvalSummary`.
